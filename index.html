Reference Overview

Why we're showing you this

We're not here to walk you through how to build these tools. Half of you could build them faster than we did. What we want to slow down, together, on day zero, are the two questions we think actually decide whether any of this matters: what should we build, and who is it actually for.

The Opportunity Algorithm makes us name what's underserved before we fall for a solution we just think is cool. The Simulation tab makes "the user" a person with specific, occasionally annoying behavioral data instead of a vibe we're projecting onto. The Cosine Similarity tool checks whether the cohort we think we're building for actually shares a preference — because if they don't, we're not solving one problem, we're solving three and pretending it's one.

Our bet for today: speed of experimentation beats speed of execution. We'd rather rule out five bad directions before lunch than polish one we never tested. This is the start of the questions, not the start of the answers — so if something we try today falls apart, that's not a bad demo, that's the point.

— Team [X], Day 0 Orientation

Interactive Module Rules

01. Opportunity Scoring

Score opportunities using Importance and Satisfaction. Ripe sectors (high importance, low satisfaction) are colored green.

02. Data Simulation

Adjust behavior metrics and interest tags. All inputs are editable inline. Export to download valid JSON data structure.

03. Cosine Matching

Toggle similarity views to sort people. The matrix dynamically calculates proximity. Self-pairs highlight along the diagonal.

04. Session Integrity

All analysis runs client-side in the browser. Clear or reload the page to restore seed values to default.

Opportunity Algorithm

Score any user or customer need by how important it is versus how satisfied people currently are.

Importance + max(Importance - Satisfaction, 0) = Opportunity
